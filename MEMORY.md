## Decisions
- **Fail closed**: a code path that forgets to declare a project sees nothing, rather than everything. Platform routes are an explicit allow-list in `registerAuth`.
- **Owner vs app account**: migrations (and test setup) run as the owner; the server never does, so a bug or injection cannot disable the policies.
- **Roles live on memberships; Super Admin is a flag**, so the same person can hold different roles per project and platform power can never leak into a project role (platform keys are filtered out of every project role).

## DYNAMIC WORKFLOW & TEMPLATING ENGINE — plan (directive: FEATURE_DYNAMIC_WORKFLOWS.md, 2026-10-28)

**Principle.** Today the ticket lifecycle is hard-coded (Postgres enum `ticket_state`, a linear trigger, `stateMachine.ts`, a `GATED` map, board lanes in the web app). It becomes data. The existing nine-step lifecycle survives unchanged as the seeded **Waterfall** template, so every current project, test and document rule keeps working.

**Data model (migration 019+).**
- Masters (platform-owned, Super Admin editable, readable by every project): `template_types` (Waterfall, Agile, Hybrid, ITIL), `project_types` (Implementation, Support, DevOps, Conversion), `ticket_types` (Requirement, Incident, Problem, Change Request, RITM, WRICEF, Feature, Bug, Epic), `phases` (the 9 existing + ITIL/Agile/Hypercare/Closed phases; carries a board `lane` tone and a colour).

- `tickets.current_state` (and `ticket_transitions.*_state`) change from the enum to TEXT holding the phase name. The linear trigger is replaced by one that asks SQL function `next_phases(project, ticket_type, from_phase)`, a recursive CTE over the project's template that **skips disabled phases** (so switching off *Hypercare* just bypasses it). The database still refuses illegal jumps, now per project and ticket type.
- RLS on the new per-project tables; masters have no project column and are read-only to the app account except through Super Admin routes.
- Backfill: every existing project becomes Implementation + Waterfall with all nine phases on (Hypercare/Closed off), ticket type Requirement; every ticket gets type Requirement.

Reports/dashboards/ETL/doc rules stop importing the static `STATES` list (they read the project's phases; document rules stay keyed by phase *name*, so docs simply never apply in a project whose template has no FS/TS phases).
